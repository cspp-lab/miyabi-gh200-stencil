# OSU Micro-Benchmarks on MVAPICH-Plus 5.1.0rc (Miyabi-G) — 2026-11-09

- MPI: MVAPICH-Plus 5.1.0rc (`cuda13.3/ucx/.../gcc11.3.1`), UCX 1.19.0 (`/work/share/ucx/1.19.0-gcc11`)
- OMB: 7.5.3 (`/work/share/benchmarks/Miyabi-G/osu-microbenchmarks-7.5.3-MVAPICH-Plus-5.1.0rc`)
- 実行: pbswrap v34 (MVAPICH テンプレート, Hydra + `pbs_tmrsh_wrapper.sh`)。モジュール `gcc cuda/13.4 nccl`、`MVP_ENABLE_GPU=1`
- ノード: GH200 120GB × 1 GPU/ノード、InfiniBand NDR200 (25 GB/s)
- ジョブ本体: `job/gen.sh` で生成 (`A_pt2pt_inter.sh` `B_pt2pt_intra.sh` `C_multipair.sh` `D_coll.sh`)
- H = ホストバッファ, D = GPU バッファ (`-d cuda`)

## ⚠ GPU バッファの縮約演算が大きいサイズで失敗する

`libmpi.so` に含まれる CUDA カーネルは sm_75(PTX 9個のみ)/sm_80/sm_100/sm_120 で、**sm_90 (GH200) 向けがない**
(`cuobjdump --list-elf`、job 3845192)。sm_80 のバイナリは sm_90 では動かないため、
yaksa の pack カーネルや MVAPICH の `localreducedst` / `multilocalreduce` カーネルが
`no kernel image is available for execution on the device` で失敗する。

| ベンチマーク | 2ノード | 4ノード | 8ノード |
|---|---|---|---|
| allreduce (D) | ≤4MB OK, 8MB で失敗 | 同左 | 同左 |
| reduce_scatter (D) | 16MB まで OK | 16MB で失敗 | 16MB で失敗 |

`-c` で検証すると、失敗するサイズより小さい範囲はすべて Pass(別の経路で処理されている)。
**sm_90 を含めて再ビルドしたもの(`-gencode arch=compute_90,code=sm_90`)が必要**。H バッファの縮約は問題なし。

# MVAPICH-Plus 5.0.1 との比較 — 2026-11-09

- 実行: pbswrap テンプレートを 5.0.1 に切り替え(`.../MVAPICH-Plus/5.0.1/.../lib`, `libmpi.so.11`, UCX 1.19.0)。
  OMB は `osu-microbenchmarks-7.5.3-MVAPICH-Plus-5.0.1`。ジョブ本体は `job/gen.sh 5.0.1` で生成した `job/5.0.1/`(違いは OMB のパスのみ)。
- job: A 3846484, B 3846485, C 3846486, D 3846491 (N=2) / 3846492 (N=4) / 3846493 (N=8), 検証 3846487, アーキテクチャ確認 3846578

## ⚠ 5.0.1 は GPU バッファの縮約演算で誤った結果を返す(異常終了しない)

- `libmpi.so.11` の CUDA カーネルも sm_75(PTX 2個のみ)/sm_80/sm_100/sm_120 で、**sm_90 がない**(5.1.0rc と同じ)。
- 同じ `no kernel image` エラーが出るが、5.0.1 では **rc=0 で 16MB まで最後まで走る**。
- `-c` で検証すると、allreduce (D) と reduce_scatter (D) は **2MB 以上で Validation Fail**(2ノード)。
  2MB 以上の D の allreduce・reduce_scatter の時間は、誤った計算を測った値なので意味がない。
- 5.1.0rc は 8MB 以上(allreduce)で rc=1 で異常終了し、それ未満は検証 Pass。誤った結果を返さない分、5.1.0rc の方が安全。
